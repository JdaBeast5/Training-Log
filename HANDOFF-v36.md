**rgba() literal → CSS custom-property consolidation (v3.171, v3.172):**
Continuing a prior session's H2.1 work (which only tokenized `box-shadow`/`filter` glow literals into `--plate-{red,blue,yellow,green,orange}-rgb` companions and explicitly deferred `background`/`border`/`gradient` literals). This session closed that out completely:
- v3.171 (H2.2): red/green/orange/teal/purple — 38 sites. Added two new companions (`--plate-teal-rgb`, `--plate-purple-rgb`) since those colors had 3+ real repeat sites with no existing companion.
- v3.172 (H2.3): blue/yellow — the last 57 sites, closing out all 7 plate-family colors.
- **~212 rgba() literals remain, deliberately untouched**: white/black/surface neutrals (not part of the accent palette), and colors that are *close to* but not byte-identical to a plate color (explicitly not merged — treated as a real different shade, not drift, matching the discipline an even earlier pass (H2.3, the gradient-color one, confusingly a different "H2.3" name in an older session — see git blame if this matters) already established for near-but-not-identical CTA gradient colors).
- Testing note for whoever touches this next: **jsdom's CSSOM does not resolve CSS custom properties in `getComputedStyle` at all** — a `var()`-based `rgba()` and an unset property both compute to the same `rgba(0,0,0,0)` regardless of what the variable holds. A naive before/after `getComputedStyle` diff proves nothing for this class of change. The tests here use a real-cascade string-substitution proof instead (extract the real `:root` block, substitute the real companion value, assert byte-identical to the original literal) — copy that pattern, don't reinvent it.

## 5. Standing practices this session followed (inherit these)

`bash check.sh` before and after every change, including after every version bump (line-number drift has caused false test confidence before). Real jsdom tests extracting actual source — never string-matching, never reimplementing logic under test. Sabotage-verify: revert, confirm the test fails, restore via a surgical string-replace script (never `git checkout`, which reverts the whole file and can wipe out unrelated uncommitted work — this bit once this session, see §3). `APP_VERSION`/`VERSION` bumped together for every user-facing change, skipped for pure-internal/test-only changes, each with a `WHATS_NEW` entry in this app's established plain-language voice. Background forks/agents never push — commits are reviewed diff-by-diff, rebased onto the current tip, version-numbered conflicts resolved by hand (choosing the next sequential number, amending the stale number out of the commit subject/body too, not just the code), re-tested post-rebase, live-verified, merged `--ff-only`, re-tested again, then pushed. `git worktree remove --force` throws a Windows/OneDrive permission-denied error on the internal `.git/worktrees/<name>` metadata folder every time — harmless noise, confirmed via `git worktree list` that removal still succeeds; don't chase it.
