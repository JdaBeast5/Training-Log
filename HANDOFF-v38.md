## 1. What shipped

**v3.192 — Barcode scans recognize a repeat item from My Foods instantly.** User asked to "add the save to My Foods function after scanning a barcode" — turned out that part already worked (verified with a real invocation before building anything: `addFoodToLog` already caches anything with `item.source` set, and `lookupBarcode` already set `source: 'Open Food Facts'`). The actual gap: rescanning the same physical barcode still did a fresh network lookup every time. Fixed by having `lookupBarcode` return the barcode on the item (rides along into the cached My Foods entry for free) and `handleBarcodeFound` check `customFoods` for a matching barcode before hitting the network. `test-barcode-my-foods-cache.js` (4 tests, sabotage-verified) plus a real headless-Chromium session confirmed: first scan makes exactly one fetch call, second scan of the same barcode makes zero.

**v3.193 — Citation currency check finished.** The user asked to "finish the other 46 citation entries" after the prior session's Pilates/ACL Rehab/Boxing S&C pass. Method: 6 background research agents in parallel, each covering a batch of entries by shared citation cluster (not always 1:1 with entries — e.g. 8 entries share the same ACSM 2026 position stand, checked once not eight times). Every claimed update was independently re-verified via direct web search (DOI, journal name, page range, author list) before being written into the file — this caught real discrepancies worth knowing about for next time:
- One research agent's page-range claim for the bariatric citation (546-547) conflicted with a second search (606-614) — resolved by a third, more targeted search that confirmed 606-614 was correct. Never take a single agent's citation claim at face value, even after one search — cross-check ambiguous details a second way.
- This mirrors the prior session's finding (a wrong DOI suffix for the APKASS consensus statement) — subagent-reported citation details are leads, not ground truth, every single time.

**9 entries received real, verified updates** — see the git log / WHATS_NEW 3.193 entry for the short version. The one worth specifically flagging to whoever picks this up: **road cycling**'s new citation (Rosenblat et al. 2025, a network meta-analysis) found the ideal training-intensity distribution differs between competitive and recreational riders — polarized favors competitive, pyramidal favors recreational. This app's Road Cycling program doesn't currently distinguish user competitive level when recommending or building the program. That's a **real, live tension between what the citation now says and what the program does**, deliberately not resolved in this pass (out of scope — a citation-currency check isn't a program-redesign task) and flagged plainly in both the `primary` and `editorNote` fields rather than smoothed over. If someone wants to make the program itself smarter about this, that's a real, well-scoped next feature.

**~35 other entries checked and confirmed still current.** Notably: boxing's head-impact-safety gap (no citation exists addressing concussion/head-trauma risk from training, only round-intensity data) is still genuinely open — two 2023/2025 papers were found and evaluated, neither one responsibly closes the gap (one documents that the evidence itself "remains poorly characterised," the other is competition-outcome data, not training-safety guidance) — so it stays flagged as an open gap rather than papered over with an adjacent-but-wrong citation. Same discipline as the McGill/Alfredson entries staying deliberately old: not every gap should be filled just because a search was run.
